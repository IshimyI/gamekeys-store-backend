# GameKeys Store — тестовое задание (Backend)

Ядро магазина цифровых товаров для геймеров: заказы, вебхук оплаты, выдача
кода из пула через двух поставщиков-заглушек (с таймаутами и fallback),
восстановление после сбоев. Без фронтенда — только REST API.

## Как запустить

Нужен Node.js 22.5+ (используется встроенный `node:sqlite`, ничего собирать не надо).

```bash
cd server
npm install
npm run seed      # создаёт server/data.sqlite, добавляет товары и пул ключей
npm start         # http://localhost:3000
```

Для воспроизводимых тестов лучше запускать без случайных сбоев поставщика:

```bash
npm run start:deterministic
```

## Как проверить гонки, таймауты и fallback

```bash
cd server
npm run load-test   # сервер должен быть уже запущен
```

`scripts/load-test.js` прогоняет все сценарии из критериев приёмки: 50
параллельных вебхуков с одним и с разными event_id, вебхук раньше заказа,
таймаут поставщика ≠ отказ, поставщик A недоступен → fallback на B, пустой
склад → восстановление, и сверку денежного леджера.

## Ключевые решения

Коротко — в `NOTES.md`. Там же: как обеспечена однократная выдача, ретраи с
бэкоффом и fallback A→B, сверка/леджер, фоновое восстановление зависших
заказов, и отдельно — design-заметка про каталог на тысячах SKU и как бы
масштабировали систему под нагрузку.

## Что сделано по этапам

- **Этап 1** — REST-ядро: создание заказа, получение по id, вебхук оплаты,
  авто-выдача из пула, статусы.
- **Этап 2** — exactly-once под гонками (параллельные и дублирующиеся вебхуки).
- **Этап 3** — два поставщика-заглушки со случайными сбоями/таймаутами,
  ретраи с бэкоффом на одном поставщике, fallback A→B, ловушка таймаута
  закрыта (повтор после таймаута не создаёт вторую выдачу).
- **Этап 4** — структурные JSON-логи по платежам и выдаче, эндпоинт сверки
  `GET /api/admin/reconciliation`, фоновая задача на зависшие заказы,
  денежный леджер.
- **Этап 5** — design-заметка про индексы и запрос витрины остатков на
  тысячах+ SKU (в NOTES.md, без генерации фейковых данных).

## API-документация

`openapi.yaml` в корне — OpenAPI 3.0 спека по всем эндпоинтам. Можно открыть
в Swagger Editor (editor.swagger.io → File → Import file) или в любом
OpenAPI-вьюере.

## Эндпоинты

- `GET /api/products` — каталог.
- `POST /api/orders` — создать заказ (`{ sku }`).
- `GET /api/orders/:id` — статус заказа.
- `POST /api/webhooks/payment` — вебхук оплаты (контракт из задания).
- `GET /api/admin/undelivered-orders` — заказы в восстановимом состоянии.
- `GET /api/admin/reconciliation` — сверка леджера и заказов.
- `POST /api/admin/orders/:id/retry` — ручная повторная выдача (идемпотентна).
- `POST /api/admin/restock` — пополнить пул ключей.
- `POST /api/test/force-delivery` — форсировать сценарий поставщика для тестов
  (`{ order_id, forceA, forceB }`, значения `success | error | timeout`).

## Что не делал специально

Фронтенд, реальный эквайринг и реальных поставщиков, Docker/CI, per-SKU пул
ключей (общий пул хватает для проверки конкурентности; как бы делал по-другому
на масштабе — в NOTES.md).
